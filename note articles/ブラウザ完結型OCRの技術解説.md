# 数独アプリの盤面解析を支える技術：ブラウザ完結型OCRの裏側

「Antigravity Sudoku」の開発において、最も技術的に挑戦し、かつこだわった機能の一つがOCR（光学文字認識）による盤面取り込み機能です。

[Antigravity Sudoku — Overview](https://qootheskywalker.github.io/Antigravity/sudoku/index.html)

ネット上の難問を、自分が作った最高のUIで解きたい。そんな動機から始まったこの機能ですが、ブラウザ上だけで、しかもサーバーを介さず「プライバシーを守りながら高速・正確に」実現するまでには、いくつかの技術的なドラマがありました。
本記事では、エンジニアの方向けに、その内部で動いている「盤面認識アルゴリズム」のステップをご紹介します。

## 1. どこからが数独か？：OpenCV.jsによる枠検出
最初の難関は、投稿された画像（スクリーンショットなど）から正確に数独の「9x9の正方形」を切り出すことです。

ここでは、画像処理ライブラリの定番OpenCV.jsを活用しています。適応的二値化（Adaptive Thresholding）によって、暗い場所で撮られた写真や低コントラストな画像からもノイズを除去し、輪郭を抽出します。

単に最大の四角形を探すだけでは、背景のウィンドウや他の要素を誤検知してしまいます。そこで、抽出した輪郭の中から「アスペクト比がほぼ1:1であること」「十分な面積を持っていること」といった条件でフィルタリングを行い、グリッドの四隅を特定します。この処理のおかげで、画像内のどこに数独があっても、ピタリと抜き出すことが可能になりました。

## 2. 黒い盤面にも対応：ノイズ除去と正規化の工夫
切り出した9x9の盤面を81個のセルに分割した後は、それぞれの数字を「読みやすく」するための整形処理が重要です。

まず面白いのが「ダークモード」への対応です。セルの平均輝度を解析し、背景が黒い場合はビット反転を行ってから処理に進みます。これにより、どんなカラーテーマのサイトから持ってきた画像でも、同じアルゴリズムで解析できます。

次に、ノイズ除去です。セルの境界線（グリッド線）が少し残っていると、OCRはそれを数字の一部と勘違いしてしまいます。そこで、連結成分解析を行い、「セルの端に触れているピクセル」をグリッド線として一掃し、「セルの中央に浮いている最大の島」だけを抽出します。

最後に、抽出した数字を128x128ピクセルのキャンバスの中央に配置し、サイズを統一する「スケーリングと正規化」を行います。この一連の清掃作業こそが、後に続くOCRの精度を劇的に向上させる鍵となります。

## 3. 計算コストを1/10に：Glyph Grouping（グルーピング）
通常、81個のマスそれぞれに対してOCRを実行すると、ブラウザのCPU負荷は跳ね上がり、ユーザーを数秒待たせてしまいます。これを解決したのが「Glyph Grouping」という手法です。

人間が見れば「これは『5』だ」とわかる数字は、盤面内に複数存在します。プログラム的にも、正規化した後の画像同士を比較（テンプレートマッチング）すれば、それが同じフォントの同じ数字であるかは高い精度で判別できます。

1. 81マスのうち、数字があるマス同士を画像比較でグループ化する。
2. グループごとに1回だけOCRを実行する。

この仕組みにより、OCR（Tesseract.js）の呼び出し回数を最大81回から、わずか10回程度（1〜9の数字＋空欄）まで削減しました。解析スピードは一気に実用レベルまで加速し、ユーザー体験を損なわない高速な取り込みが実現したのです。

## 4. OCRすら超える、「自ら学ぶ」究極の回避策
しかし、どんなに優れたOCRエンジンでも、あまりに特殊なフォントや手書き風の数字、ノイズの激しい画像では、どうしても「認識不能（?）」となってしまうことがあります。

「100%の自動認識」は理想ですが、一部でも読み取れないマスがあるとプレイが始められません。そこで、開発の最後に私が思いついた「驚きの方法」を実装しました。
それは、「ユーザーの修正内容を永続化し、自己学習するパターンマッチング・エンジン」です。

もしOCRが数字を特定できなかった場合、ユーザーに手入力を求めます。ユーザーが正しい数字を教えると、アプリはその「未知のフォント画像」と「正解の数字」のペアをブラウザのlocalStorageにキャッシュします。
次にユーザーが同じサイトの問題を取り込もうとした際、アプリはOCR（Tesseract）を回す前に、まずはこの「学習済みキャッシュ」と画像比較を行います。過去に一度でもユーザーが教えてくれたフォントであれば、OCRが「?」と匙を投げた画像であっても、0.1秒以下で、かつ100%の精度で認識が完了します。

使えば使うほど、あなたの環境に最適化され、賢くなっていく。現在のバージョンではOCRの誤認識そのものはほぼ発生していませんが、この「未認識をユーザーの手を借りて克服し、二度と同じ場所で迷わない」仕組みこそが、実務上の認識精度を100%に引き上げる最後の一手となりました。

## 結びに
ブラウザという制限の多い環境で、いかに効率よく、かつ「絶対に裏切らない」ツールを作るか。
その答えが、OpenCVによる愚直な前処理、グルーピングによる負荷削減、そしてユーザーの力を借りて進化するキャッシュ機能の組み合わせでした。
数独というシンプルなゲームの裏側で、これほどまでに熱い技術的思考が動いている。そう感じていただければ、開発者としてこれ以上の喜びはありません。
